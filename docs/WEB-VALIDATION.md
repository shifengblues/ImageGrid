## 本地图像处理

- 图片通过文件选择器、文件夹选择器或拖放读取，使用用户设备的 CPU/内存处理。
- 优先使用 Worker 与 OffscreenCanvas；不支持 OffscreenCanvas 的浏览器使用本机普通 Canvas 兼容路径，纯 PNG 像素与压缩任务仍可在 Worker 内完成。兼容路径的部分任务可能短暂占用主线程，取消在异步阶段或当前步骤结束后生效。
- 所有依赖随静态网站构建，不使用第三方 CDN、图片上传服务或统计脚本。生产构建设置 CSP `connect-src 'none'`、`form-action 'none'`，禁止网络数据连接和表单提交。静态页面、脚本、Logo 的正常 GET 请求及 GitHub 托管本身的访问日志仍然存在。
- 文件夹写入需浏览器支持并授权，输出放在新建的唯一子文件夹内；通用保存方式为 ZIP。

## 三轮浏览器检查

1. Chrome 主流程：16 项具名检查，包含 PNG/JPEG/WebP/BMP 导入、合成、间距与超容量刷新、真实拖动排序、删除、清空确认/取消、选色非法输入、拆分坐标、页面切换保留分界线、窄屏排版、无上传请求、无运行时错误。
2. Chrome 错误恢复：13 项具名检查，包含部分导入失败、单张拖放替换失败保留原图、超大 PNG 头提前拒绝、空行列输入、HEX 确认、隐藏合成错误不阻塞拆分、实际鼠标拖动分割线、过大内缩拒绝、Escape 取消、文件夹过滤、取消导入和恢复导入。
3. WebKit 引擎：PNG 合成、原像素 PNG/JPG、拆分 ZIP、文件夹写入不可用时回退 ZIP、浅深色、窄屏、无上传请求和无运行时错误。不支持 OffscreenCanvas 的此引擎构建最初不能导入，已加入兼容路径并复测通过。

发现并修复：小图放大时，SVG 分割线命中范围因缩放而覆盖其他线。按实际屏幕缩放反算命中宽度后，真实鼠标可将 16×9 测试图纵线从 8px 拖至 5px。另移除主题切换时按钮背景的过渡，避免切换瞬间文字对比不足。

## 实际导出文件验证

- Chrome 和 WebKit 均下载并重新解码 PNG/JPG。120×90 小图与 320×180 大图混排，默认输出 643×363；60px 间距输出 700×420，核对整条间距宽度及颜色。
- 原像素 PNG 输出逐像素比较测试源图，包含半透明和完全透明像素的 RGB 值。PNG 原像素与拆分使用独立 PNG 编解码，避免 Canvas 预乘透明度损失。
- Chrome/WebKit 的拆分 ZIP 解压，逐张核对整数分割尺寸与全部像素；修改分界线、设置内缩后的结果也逐像素比较。
- Fit 保持完整内容与留白，Fill 居中裁切，下载文件实际取样区分两种效果。
- Chrome 实际导入四张 3840×2160 图片并导出 7683×4323 PNG，重新解码核对完整尺寸，没有降采样。
- 8 项 Node 单元检查覆盖布局、等比填充、容量/参数拒绝、整数分割、排序、PNG 透明/索引色/灰度透明、JPEG 背景合成。TypeScript 类型检查和生产构建通过；生产依赖 npm audit 未报告漏洞。

## 验证边界

浏览器运行环境为当前 Windows 机器上的 Chrome 和 Playwright WebKit，后者不等于 macOS 实机 Safari。未覆盖所有设备内存、系统色彩管理及浏览器版本。文件选择结果由浏览器测试提供；真实系统文件夹写入授权未自动化操作，不声称已经验证用户的任意磁盘权限组合。

网页预览使用最长边 640px 缩略图，放大可能模糊；导出读取源图。仅支持首帧和 8 位输出，暂不保存工作区，也没有离线安装缓存。预计像素缓冲上限不等同于浏览器总进程内存保证。
